# Checklist

> 模板：learning-task | 默认「教程类」变体
> 技术文档阅读变体见下方「变体：技术文档阅读」

## 核心概念（Task 1）
- [ ] 核心概念数量不少于 5 个
- [ ] 每个概念有清晰的定义和解释
- [ ] 概念间无混淆或重复

## 技术原理（Task 2）
- [ ] 工作机制/原理阐述清晰、逻辑连贯
- [ ] 至少包含 1 张 Mermaid 图表（flowchart/sequence/state）
- [ ] 图表与文字说明一致，无矛盾

## 实践案例（Task 3）
- [ ] 操作步骤/模板/流程归纳完整
- [ ] 案例按场景分类清晰
- [ ] 案例具备可复现性（有具体步骤）

## 关键结论（Task 4）
- [ ] 结论数量在 5-8 条之间
- [ ] 结论覆盖学习内容的主要维度
- [ ] 个人理解具有可迁移性（提炼了至少 1 个可迁移模式）
- [ ] 结论有原文依据支撑，非主观臆断

## 自测问答（Task 5）
- [ ] 题目数量在 5-10 之间
- [ ] 题目覆盖核心知识点的主要维度
- [ ] 每题答案准确、完整
- [ ] 题目难度有层次（基础 + 进阶）

## 知识框架（Task 6）
- [ ] 使用 Mermaid mindmap 格式
- [ ] 覆盖全部学习模块
- [ ] 层级关系正确，无逻辑错误
- [ ] 一眼可看清知识全貌

## 整体质量
- [ ] 学习笔记结构完整（六维度齐全）
- [ ] 无事实性错误
- [ ] 语言专业、客观、简洁

---

## 变体：技术文档阅读

### API 表面积（Task 1）
- [ ] API 按模块/类别分组清晰
- [ ] 每个 API 包含名称、签名、用途描述
- [ ] 标注了 API 稳定性（public/experimental/deprecated）
- [ ] 无遗漏重要 API

### 架构与设计决策（Task 2）
- [ ] 包含至少 1 张 Mermaid 架构图
- [ ] 识别了 2-3 个关键设计决策
- [ ] 每个决策分析了原因和权衡
- [ ] 如有组件协作，职责划分清晰

### 用法模式与最佳实践（Task 3）
- [ ] 至少 2 个典型用法模式（含代码示例）
- [ ] 最佳实践清单（Do's）完整
- [ ] 反模式（Don'ts）有说明原因
- [ ] 代码示例可直接运行或接近可运行

### 约束与边界条件 + 设计评价（Task 4）
- [ ] 约束清单覆盖多维度（性能/平台/兼容性/安全/并发）
- [ ] 易错点和注意事项明确
- [ ] 设计评价独立于文档作者观点
- [ ] 明确了适用场景和不适用场景

### 快速参考卡（Task 5）
- [ ] Markdown 表格速查表完整
- [ ] 至少 1 张 Mermaid 图（调用链/状态流转/生命周期）
- [ ] 速查表可独立使用（不依赖上下文）
- [ ] 表格和图示一致，无矛盾

### API 地图（Task 6）
- [ ] 使用 Mermaid 图（flowchart/class/er diagram）
- [ ] 展示了"谁调用谁"的依赖关系
- [ ] 非知识分类树，而是实际的调用/依赖关系
- [ ] 关系正确，无遗漏关键关联

### 整体质量
- [ ] 六维度产出齐全
- [ ] 无事实性错误
- [ ] 速查表可作为独立参考文档使用
