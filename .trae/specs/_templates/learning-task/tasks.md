# Tasks

> 模板：learning-task | 默认「教程类」变体
> 六维度学习法：概念 → 原理 → 案例 → 结论 → 自测 → 框架
> 技术文档阅读变体见下方「变体：技术文档阅读」

- [ ] Task 1: 核心概念定义与解释 — 提取学习内容中所有核心概念并给出明确定义
  - [ ] 识别并提取核心概念（不少于 5 个）
  - [ ] 为每个概念撰写定义、关键特征和解释
  - [ ] 可选的附加概念表

- [ ] Task 2: 技术原理与工作机制 — 分析学习内容中的关键原理和机制
  - [ ] 阐述核心技术/机制的工作原理
  - [ ] 使用至少 1 张 Mermaid 图（flowchart/sequence/state）辅助说明
  - [ ] 如涉及多模块，分析各模块间的协作关系

- [ ] Task 3: 实践案例分析与应用场景 — 归纳学习内容中的实操案例
  - [ ] 整理操作步骤、模板或流程（如有）
  - [ ] 按场景分类归纳案例
  - [ ] 确保案例可复现（包含具体步骤和输入输出）

- [ ] Task 4: 关键结论与个人理解 — 提炼核心结论和可迁移知识
  - [ ] 归纳 5-8 条关键结论
  - [ ] 撰写个人理解段落
  - [ ] 提炼至少 1 个可迁移的设计模式、方法论或思维模型

- [ ] Task 5: 自测问答 — 设计 5-10 个关键问题并作答
  - [ ] 设计覆盖核心知识点的题目（报名流程、审核标准、奖励机制、FAQ 等维度）
  - [ ] 每题提供标准答案
  - [ ] 确保题目数量在 5-10 之间

- [ ] Task 6: 知识框架思维导图 — 构建 Mermaid 格式的知识结构图
  - [ ] 梳理各知识模块的层级关系
  - [ ] 输出 Mermaid mindmap 展示完整知识体系
  - [ ] 确保覆盖全部学习模块且层级关系正确

# Task Dependencies

```
Task 1 (概念) ──┬──► Task 2 (原理)
                ├──► Task 3 (案例)
                │
                └──► Task 4 (结论) ──► Task 5 (自测)
                                       Task 6 (框架)
```

- Task 2 依赖 Task 1（需先明确概念再进行原理分析）
- Task 3 依赖 Task 1（需先理解概念再归纳实践案例）
- Task 4 依赖 Task 1, 2, 3（需综合所有前置知识）
- Task 5 依赖 Task 1, 2, 3, 4（需覆盖全部知识点）
- Task 6 依赖 Task 1, 2, 3, 4（需综合全部知识模块）

# 并行执行建议

- Task 2 和 Task 3 可在 Task 1 完成后并行执行
- Task 5 和 Task 6 可在 Task 4 完成后并行执行

## 变体：技术文档阅读

> 六维度：API 表面积 → 架构决策 → 用法模式 → 约束评价 → Cheatsheet → API 地图

- [ ] Task 1: API 表面积概览 — 列出文档中所有公开的 API、接口、类、函数、配置项
  - [ ] 按模块/类别分组列出全部 API
  - [ ] 每个 API 包含：名称、签名（参数+返回值）、一句话用途描述
  - [ ] 标注 API 的可见性/稳定性（public/experimental/deprecated）

- [ ] Task 2: 架构与设计决策 — 分析整体架构和关键设计决策
  - [ ] 画出整体架构图（Mermaid flowchart/class diagram）
  - [ ] 识别 2-3 个关键设计决策，分析其原因和权衡
  - [ ] 如涉及多组件，分析组件间的职责划分和通信方式

- [ ] Task 3: 用法模式与最佳实践 — 归纳常见用法和推荐做法
  - [ ] 提取至少 2 个典型用法模式（含代码示例）
  - [ ] 整理最佳实践清单（Do's）
  - [ ] 整理常见反模式（Don'ts），说明为什么不该这样做

- [ ] Task 4: 约束与边界条件 + 设计评价 — 梳理限制条件和设计评估
  - [ ] 列出约束清单：性能限制、平台兼容性、安全边界、并发限制等
  - [ ] 列出易错点和注意事项
  - [ ] 撰写设计评价：技术选型的优缺点、适用场景与不适用场景

- [ ] Task 5: 快速参考卡（Cheatsheet） — 生成可快速查阅的参考卡
  - [ ] 制作 Markdown 表格速查表（常用 API/参数/配置/返回值）
  - [ ] 绘制至少 1 张 Mermaid 图（关键调用链/状态流转/生命周期）
  - [ ] 确保速查表可独立使用（不依赖上下文即可理解）

- [ ] Task 6: API 地图/概念关系图 — 构建组件间关系图
  - [ ] 梳理组件/API/概念之间的依赖和调用关系
  - [ ] 输出 Mermaid 图（flowchart/class diagram/er diagram）
  - [ ] 确保关系图展示了"谁调用谁"而非"知识分类树"
