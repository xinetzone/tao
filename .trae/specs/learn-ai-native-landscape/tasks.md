# Tasks

> 模板：learning-task | 教程类变体
> 六维度学习法：概念 → 原理 → 案例 → 结论 → 自测 → 框架
> 学习来源：关于页（主）+ 主页分类结构 + 评分方法页

- [x] Task 1: 核心概念定义与解释 — 提取学习内容中所有核心概念并给出明确定义
  - [x] 识别并提取核心概念（不少于 5 个）：AI Native Landscape、AI 原生技术栈、策展式收录、项目墓地、综合健康度评分、参考状态（观察中/已验证/代表项目/已归档）
  - [x] 为每个概念撰写定义、关键特征和解释
  - [x] 补充概念表：收录边界（收录什么/不收录什么）、信任要素等附加概念

- [x] Task 2: 技术原理与工作机制 — 分析学习内容中的关键原理和机制
  - [x] 阐述评分模型工作机制：4 维度（活跃度 A / 社区参与度 C / 影响力 Q / 持续性 S）加权计算综合健康度 0-100
  - [x] 阐述项目生命周期与参考状态流转机制（观察中 → 已验证 → 代表项目 / 已归档）
  - [x] 使用至少 1 张 Mermaid 图（flowchart）辅助说明评分计算流程或项目生命周期流转
  - [x] 分析收录/变更/归档三个流程的协作关系与触发条件

- [x] Task 3: 实践案例分析与应用场景 — 归纳学习内容中的实操案例
  - [x] 整理"如何提交一个新项目"操作步骤（GitHub Issue 表单流程）
  - [x] 整理"如何变更项目信息"操作步骤（PR 修改 data/projects/ YAML + npm run validate）
  - [x] 整理"如何归档项目"触发条件与恢复机制
  - [x] 归纳使用场景案例：按技术域浏览选型、按评分等级筛选、按参考状态判断可信度
  - [x] 梳理 8 大分类与子类的生态结构（开发者工具链、智能体系统、推理与运行时、知识与上下文工程、训练评测优化、应用与体验等）

- [x] Task 4: 关键结论与个人理解 — 提炼核心结论和可迁移知识
  - [x] 归纳 5-8 条关键结论（覆盖：站点价值主张、收录哲学、评分透明性、生态趋势、维护模式等）
  - [x] 撰写个人理解段落，结合自身知识体系对比 AI 原生生态与云原生生态的异同
  - [x] 提炼至少 1 个可迁移的设计模式/方法论（如：策展式生态地图的治理方法论、多维评分模型设计、双语维护机制等）

- [x] Task 5: 自测问答 — 设计 5-10 个关键问题并作答
  - [x] 设计覆盖核心知识点的题目（站点定位、收录边界、8 大分类、评分 4 维度、5 等级阈值、4 参考状态、提交流程、归档条件、信任要素等维度）
  - [x] 每题提供标准答案
  - [x] 确保题目数量在 5-10 之间，难度有层次（基础 + 进阶）

- [x] Task 6: 知识框架思维导图 — 构建 Mermaid 格式的知识结构图
  - [x] 梳理各知识模块的层级关系（定位 → 收录边界 → 分类体系 → 评分模型 → 参考状态 → 流程 → 趋势）
  - [x] 输出 Mermaid mindmap 展示完整知识体系
  - [x] 确保覆盖全部学习模块且层级关系正确

# Task Dependencies

```
Task 1 (概念) ──┬──► Task 2 (原理)
                ├──► Task 3 (案例)
                │
                └──► Task 4 (结论) ──► Task 5 (自测)
                                       Task 6 (框架)
```

- Task 2 依赖 Task 1（需先明确概念再进行原理分析）
- Task 3 依赖 Task 1（需先理解概念再归纳实践案例）
- Task 4 依赖 Task 1, 2, 3（需综合所有前置知识）
- Task 5 依赖 Task 1, 2, 3, 4（需覆盖全部知识点）
- Task 6 依赖 Task 1, 2, 3, 4（需综合全部知识模块）

# 并行执行建议

- Task 2 和 Task 3 可在 Task 1 完成后并行执行
- Task 5 和 Task 6 可在 Task 4 完成后并行执行
