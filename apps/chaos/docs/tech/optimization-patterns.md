> **来源**：`track-prize-optimization-report.md` + `trae-guests.md`  
> **定位**：实施推进 + 风险管控 + UX 引导 + 赛事阵容设计

## 1. 四分阶段推行模式

**通用公式**：

```
Phase 1（赛前4周）：基础设施变更 → 不可逆的架构调整先做
Phase 2（赛前2周）：信息公布     → 配合 PR 传播形成势能
Phase 3（进行中）：  动态微调     → 监控数据，预留10%浮动空间
Phase 4（赛后）：    复盘沉淀     → 标准化为下届参考
```

**可复用规则**：
- Phase 1 和 Phase 2 之间必须有 ≥ 2 周缓冲——信息公布后给受众消化时间
- Phase 3 的「动态微调」必须有量化触发条件（如蓝海赛道报名 < 目标 60% 则启动）
- Phase 4 的输出必须是一份可移交的文档，而非口头传承

## 2. 风险对策矩阵

**格式模板**：

| 风险 | 影响 | 概率 | 对策 |
|------|------|------|------|
| {负面事件} | {高/中/低} | {高/中/低} | {具体对冲措施} |

**TRAE 实践的三条范例**：

| 风险 | 对策模式 |
|------|----------|
| 受益方不满（降薪） | **非现金补偿对冲**：降低现金但增加导师/曝光/资源 |
| 引导效果不足 | **预留浮动空间**：10% 预算作为赛中二次调整池 |
| 理解成本增加 | **向导式降噪**：用 Q&A 流程替代平铺说明 |

**可复用规则**：
- 任何涉及「利益重新分配」的方案，必须配套「非现金补偿对冲」
- 任何涉及「行为引导」的方案，必须预留 ≥ 10% 动态调整空间
- 任何涉及「规则复杂度提升」的方案，必须配「推荐向导」降噪

**实战案例**：

```
规则 1 — 非现金补偿对冲：
  案例：赛事热门赛道奖金从 ¥50,000 降至 ¥35,000
  ❌ 只降不补
  ✅ 降现金（-30%），补非现金：TOP10 进技术导师计划 + 全渠道曝光 + Pro+ 年卡
  效果：参赛者认为「曝光+导师」总价值 > 差价 ¥15,000，报名热度未降

规则 2 — 预留浮动空间：
  案例：销售奖金池 100 万，向新客户开拓倾斜
  ❌ 一次性锁定「新客 70 万、老客 30 万」
  ✅ 初始分配「新客 60 万、老客 30 万」+ 浮动池 10 万
     触发：老客流失 > 5% → 从新客划拨 5 万到老客维护奖
     触发：新客超额 120% → 浮动池全奖新客
  效果：两队都认为规则公平，「浮动池」成为关注焦点而非争议点

规则 3 — 向导式降噪：
  案例：SaaS 从单套餐扩展为 5 个套餐
  ❌ 平铺 5 个套餐价格表
  ✅ Q1：个人/团队？Q2：基础够用/API 集成/私有部署？
     结果：推荐最佳套餐 + 3 个集成示例
  效果：选择完成率 40% → 78%，决策时间 5min → 45s
```

> 更多跨领域案例（研发资源、OKR、技术选型等）见 [optimization-patterns-cases.md](optimization-patterns-cases.md)

## 3. 分组专属资源包模式

**通用公式**：

```
不同组别 = 不同资源包
         ≠ 不同现金（现金可微调，但核心吸引力来自专属资源）
```

**TRAE 实践**：

| 组别 | 核心需求 | 专属资源 |
|------|----------|----------|
| 大众创作组 | 低门槛上手 | 入门教程 + 模板库 + 社区问答 |
| 专业开发组 | 深度技术支持 | API 文档 + 导师 + 算力额度 |
| 社会责任组 | 落地渠道 | 政策对接 + NGO 通道 + 媒体传播 |

**可复用规则**：
- 分组后每组必须有 ≥ 1 个「不花钱但极具吸引力」的专属资源
- 资源包与组别的对应关系必须在报名页可见（非隐藏福利）
- 专业组的资源应让大众组「向往但不可得」，形成自然分化

## 4. 赛道推荐向导 UX 模式

**通用公式**：

```
Q1：身份识别 → 分流到组
Q2：意图匹配 → 推荐具体赛道
结果：推荐赛道 + 3 个官方创意作为灵感种子
```

**设计要点**：
- 问题不超过 2 个（超过则流失）
- Q1 的选项 ≤ 3 个（「学生/普通用户」「开发者/工程师」「公益/NGO」）
- Q2 的选项来自对应组别的赛道 slogan（非赛道编号）
- 结果页给出「推荐赛道 + 即刻可用的灵感」，降低从推荐到行动的空隙

**适用场景**：任何需要用户在多选项中选择的场景（报名、注册、产品配置向导）

## 5. 代言+评审双轨阵容设计

**通用公式**：

```
赛事背书 = 领造官（公共叙事 × N 个视角） + 评委团（技术验证 × M 个维度）
           ↑ 互不重叠但交叉映射 ↑
```

**四条规则**：

| # | 规则 | 公式 | 反面案例 |
|---|------|------|----------|
| 1 | 多元叙事覆盖 | 领造官 ≥ 3 人，覆盖「表达」「市场」「工程」三角 | 4 个全是技术背景 → 丢失其他叙事 |
| 2 | 评委比例配置 | 评委 ≥ 领造官 × 1.5 | 4+4 → 某个叙事角无评委验证 |
| 3 | 身份不重叠 | 领造官 ∩ 评委 = ∅ | 代言人兼评委 → 公信力崩塌 |
| 4 | 缺失映射解读 | 有评委无领造官 = 长期布局 | 遗漏维度被误判为"被遗忘" |

**TRAE 实践**：

| 领造官 | 叙事角度 | 对应评委 | 验证维度 |
|--------|----------|----------|----------|
| 胡彦斌 | 创意能否被表达 | 快刀青衣 | 内容产品 |
| 罗永浩 | 产品能否走向市场 | 胡宇航 | 产品落地 |
| 楼天城 | 技术能否跑通 | 洪定坤 + 李东江 | 工程体系 |
| Tim | 工具能否重塑创作 | 王兴兴 | 硬件/具身智能 |

> 详细规则定义与自检清单见 [event-endorsement-rules.md](file:///d:/spaces/AgentForge/apps/chaos/.agents/docs/references/projects/trae/rules/event-endorsement-rules.md)
