# 研究项目关键决策检查清单

> **来源**：萃取自 6 个真实决策节点（TRAE 大赛研究项目），泛化为通用检查清单。  
> **使用方式**：研究项目启动/执行中逐项勾选并记录，防止遗漏关键决策。

---

## 决策 1：数据采集工具

**决策时刻**：项目启动、首次接触数据源时。

| 选项 | 适用场景 | 信号 |
|------|----------|------|
| defuddle / WebFetch | 静态网站、文档站 | `curl` 可拿到完整 HTML |
| agent-browser | SPA（React/Vue/Next.js）、登录墙后内容 | `curl` 只返回空壳 |
| 本地文件读取 | 自身仓库、内部文档 | 文件已在本地 |

**自检**：
- [ ] 是否先用轻量工具（defuddle）试过？失败后才升级
- [ ] 如果是 SPA，是否确认了 `wait networkidle` 后再提取？
- [ ] 提取方式是否选择了 `innerText` 而非 `snapshot DOM`？

**记录**：

```
目标源：{URL / 文件路径}
选择工具：{defuddle / agent-browser / 本地读取}
原因：{SPA / 静态 / 本地}
```

## 决策 2：数据提取粒度

**决策时刻**：抓取工具返回数据后，发现量级异常时。

| 选项 | 适合任务 | 风险 |
|------|----------|------|
| snapshot DOM | 交互任务（点击、表单填写、元素定位） | 虚拟列表/轮播导致节点膨胀（实测 150+ 重复） |
| `innerText` | 内容研究（文本分析、数据提取） | 丢失 DOM 结构信息 |
| 结构化 API | 有 JSON 接口的数据源 | 需额外开发 |

**自检**：
- [ ] 如果 snapshot 返回节点数 > 预期 3 倍，是否切换到 `innerText`？
- [ ] 是否确认了任务类型（交互 vs 内容研究）再选粒度？

**记录**：

```
选择粒度：{snapshot / innerText / API}
原因：{交互任务 / 内容研究 / 有API}
```

## 决策 3：研究框架维度数量

**决策时刻**：从洞察转向框架构建时。

| 选项 | 适用场景 | 缺点 |
|------|----------|------|
| 3 维 | 快速扫描、初步对比 | 区分度不足，不同对象趋同 |
| 5 维 | 标准竞品分析、深度评估 | —（推荐） |
| 7 维及以上 | 学术级全面评估 | 评分疲劳，执行成本高 |

**自检**：
- [ ] 维度是否覆盖了研究对象的核心区分要素？
- [ ] 是否避免了「为全面而全面」（> 7 维）或「为省事而省事」（< 3 维）？
- [ ] 每维度是否都能独立产出有意义的结论？

**记录**：

```
维度数：{3 / 5 / 7+}
维度列表：
  1. {维度名}：{关注什么}
  2. ...
```

## 决策 4：维度权重分配

**决策时刻**：框架维度确定后。

| 选项 | 适用场景 | 信号 |
|------|----------|------|
| 均分 | 所有维度战略重要性相同 | 极少见，通常是回避判断 |
| 加权 | 有明确的战略优先级 | 权重差异化本身就是研究结论 |

**自检**：
- [ ] 最高权重是否 ≥ 最低权重的 2 倍？（如 30% vs 10%）
- [ ] 权重分配是否反映了团队/产品的战略重点？
- [ ] 总和是否为 1.0？
- [ ] 是否跑了边界值测试（全 1 / 全 3 / 全 5）验证评分体系自洽？

**记录**：

```
{维度名}：{权重}%
{维度名}：{权重}%
...
合计：{100}%
```

## 决策 5：优化方案的力度控制

**决策时刻**：发现短板后设计优化方案时。

| 原则 | 正确做法 | 避免 |
|------|----------|------|
| 预算控制 | 内部重新分配（零增长） | 直接追加预算 |
| 力度把控 | 温和调整（±20-30%） | 极端调整（翻倍/腰斩） |
| 可逆性 | 预留浮动空间（±10%） | 一次性锁定 |

**自检**：
- [ ] 优化方案的总预算是否零增长（内部腾挪而非追加）？
- [ ] 调整幅度是否控制在 20-60% 范围内（避免过度刺激）？
- [ ] 是否为热门赛道/方向配套了非现金补偿（导师/曝光/资源）以对冲降薪不满？

**记录**：

```
优化目标：{要解决的短板}
调整幅度：{+/- X%}
预算来源：{从哪个方向腾挪}
配套补偿：{非现金权益}
```

## 决策 6：输出密度选择

**决策时刻**：面向不同受众输出报告时。

| 选项 | 适用受众 | 篇幅 | 包含内容 |
|------|----------|------|----------|
| 摘要版 | 管理层、快速同步 | 1 页 | 一句话结论 + 关键数字 + 待对齐项 |
| 标准版 | 团队内部、项目归档 | 10 章 | 完整四阶段 + 决策 + 问题 + 方法论 |
| 详细版 | 培训材料、深度复盘 | 20-30 页 | 标准版全部 + 详尽附录 + 原始数据 |

**自检**：
- [ ] 是否根据受众选择了合适密度？（不要给管理层 30 页，不要给归档留 1 页）
- [ ] 标准版是否覆盖了「决策」和「问题」两章？（复盘中最有价值的部分）

**记录**：

```
受众：{管理层 / 团队 / 归档}
选择密度：{摘要 / 标准 / 详细}
```

## 决策时间线速查

```
项目启动 ──→ 决策1(工具) + 决策2(粒度)
    │
数据完成 ──→ 决策3(维度数) + 决策4(权重)
    │
评分完成 ──→ 决策5(优化力度)
    │
报告输出 ──→ 决策6(密度)
```
